## 0. 本書の位置づけと読み方

### 0.1 目的

本書は、HADO コート予約システムの **画面UI について「要件定義段階で既に決まっていること」を整理・再構成した確定事項集**である。
出典は以下の3ドキュメントに限る。

| 出典記号 | ドキュメント |
|---|---|
| 【要求】 | `01_要件定義/アプリケーション要求機能.md` |
| 【ワイヤ】 | `01_要件定義/画面ワイヤー下書き.md` |
| 【残タスク】 | `01_要件定義/要件定義残タスク.md` |
| 【個情】 | `01_要件定義/個人情報保護方針.md` |

### 0.2 表記凡例

- **※補完** … 出典に直接の記述はないが、他の確定要件から論理的に導かれるもの。**未承認の暫定案**であり、レビューで確定させる必要がある。
- **※未確定** … 決まっていないため本書では確定させない。対応する残タスクIDを `画面UI_要件定義残タスク.md` に記載する。
- **※記述矛盾** … 出典間で記述が食い違っている箇所。本書では確定させず、残タスクに送る。

### 0.3 本書が扱わない範囲

- React コンポーネントの実装（frontend-developer の担当）
- DB設計 / API設計 / インフラ構成
- 実装しない機能の画面（チェックイン / 決済 / レビュー / レポート / 利用分析 / キャンセル待ち）【要求「実装しない機能」】

## 1. UI共通要件（確定）

【要求「ユーザーインターフェース」】より、以下は確定要件である。

| # | 項目 | 確定内容 |
|---|---|---|
| C-01 | 対応ブラウザ | Chrome / Firefox / Safari / Edge の**最新版** |
| C-02 | レスポンシブ | PC / スマートフォン / タブレットで表示可能とする |
| C-03 | アクセシビリティ | **WCAG 2.1 AA に準拠する**（必須要件） |
| C-04 | 言語 | ブラウザ設定に依存し、**デフォルトは日本語** |
| C-05 | タイムゾーン | **日本（JST）固定**。画面上のすべての日時は JST で表示する |
| C-06 | 応答時間 | 画面表示は**3秒以内**、予約登録は**5秒以内**に完了【要求「パフォーマンス要件」】 |
| C-07 | セッション | 30分間無操作で自動ログアウト【要求「セキュリティ」】 |
| C-08 | 同時ログイン | 2重ログイン不可・**後勝ち**（既存接続は強制切断される）【要求「ユーザー認証・登録機能」】 |

> C-06 は UI 側の含意として、3秒を超えうる処理には読込中表示が必須であることを意味する（具体的な閾値・表現は ※未確定）。
> C-07 / C-08 は「画面上でユーザーに何が起きたか伝える必要がある」ことを意味するが、その画面表現は ※未確定。

### 1.1 レイアウト・ブレイクポイント（確定）

【ワイヤ「レイアウト・レスポンシブ指針」】より。

| デバイス | 幅 | レイアウト方針 |
|---|---|---|
| モバイル | ≦ 640px | 縦スクロール中心。**スイムレーンは日別縦表示へ切り替える** |
| タブレット | 641px 〜 1024px | （方針の明記なし ※未確定） |
| デスクトップ | ≧ 1025px | 左右ペイン構成（左＝拠点リスト／右＝スイムレーン） |

> モバイルの「日別縦表示」は方向性のみが決まっており、**具体的な表示仕様は未確定**。

### 1.2 コンポーネント優先実装順（確定）

【ワイヤ「コンポーネントリスト」】より。

1. スイムレーンコンポーネント（表示／ブロッククリックハンドリング）
2. 日付／時間ピッカー
3. 予約フォーム（バリデーション含む）
4. モーダル共通コンポーネント
5. 拠点一覧サイドバー

## 2. 利用者ロールと画面上の権限（確定）

【要求「利用者」】より、ロールは4種。

| ロール | 画面UI上の特徴 |
|---|---|
| メンバー | 予約の閲覧・作成・参加、自分の予約の編集/削除、お気に入り登録、プロフィール編集 |
| チームリーダー | メンバーの全操作＋チーム管理（承認・編集）、チームとしての予約作成/編集/削除、他チームの空きチーム枠への参加申請 |
| 拠点スタッフ | **自拠点のみ**管理・閲覧可能。拠点情報/コート/設備/営業日時の管理、コート予約の登録・編集・削除、イベント予約、利用不可設定。**各拠点1アカウントを共有** |
| システム管理者 | 全データの登録/編集/削除、チーム・リーグ戦チーム申請の承認、拠点の追加/削除、**全予約の編集・削除** |

### 2.1 画面UIに直結する権限ルール（確定）

- 予約の編集・削除は**予約者のみ**可能。ただしシステム管理者は全予約が可能【要求「予約」】
- 拠点スタッフは**自拠点のみ**管理・閲覧可能【要求「拠点スタッフ」】
- 拠点スタッフの操作は全てログに記録される【要求「拠点スタッフ」】
- 所属チーム申請・リーグ戦所属チーム申請は**各1つのみ**申請可能【要求「メンバー」】
- チームは**リーダー1名＋メンバー9名まで**【要求「チーム」】

> 画面要素レベルの権限差分マトリクス（どのボタンが誰に見え／押せるか）は ※未確定。

### 4.1 SCR-M01 メイン画面（拠点選択＋スイムレーン）

#### 目的

拠点と日付を選択し、その拠点のコートごとの予約状況を 30分刻みのスイムレーンで俯瞰する。本システムの中核画面。

#### ワイヤー（デスクトップ ≧1025px）

```
┌───────────────────────────────────────────────────────────────────────────┐
│ [ロゴ]        [ 検索ボックス            ]        [🔔通知] [ユーザーメニュー]│ ← Header
├──────────────┬────────────────────────────────────────────────────────────┤
│ 拠点リスト   │  [◀] 2026-07-26 (日) [▶]   [日付ピッカー]  [ズーム:30分▾]  │
│              ├────────────────────────────────────────────────────────────┤
│ ★ お気に入り │        10:00  10:30  11:00  11:30  12:00  ...  21:30  22:00│
│ ┌──────────┐ │       ├─────┼─────┼─────┼─────┼─────┼ ... ┼─────┤        │
│ │[画像] A店│★│ Aコート│  ████████████████  │     │           │        │
│ └──────────┘ │       │  チーム予約 6/9名   │     │           │        │
│ ┌──────────┐ │       ├──────────────────────────────────────────────────│
│ │[画像] B店│★│ Bコート│        │  ██████████  │  ████████  │            │
│ └──────────┘ │       │        │  個人 4/6名  │  イベント  │            │
│              │       ├──────────────────────────────────────────────────│
│ すべての拠点 │ Cコート│  ▨▨▨▨▨▨ 利用不可 ▨▨▨▨▨▨  │            │        │
│ ┌──────────┐ │       │                                                  │
│ │[画像] C店│☆│       │                                                  │
│ └──────────┘ │       ▲空き枠（クリックで予約作成 ※導線未確定）          │
└──────────────┴────────────────────────────────────────────────────────────┘
```

キャプション：
- 左ペイン＝拠点リスト。**お気に入り拠点を上部に表示**する。各拠点は「画像 ＋ 名称 ＋ お気に入りボタン」で構成【ワイヤ 1】。
- 右メイン＝スイムレーン。**横軸＝時間、縦軸＝コート**【ワイヤ 1】。
- 上部に日付ピッカーと時間ズームを置く【ワイヤ 1】。
- 図中の予約ブロック内テキスト（「チーム予約 6/9名」等）は表現例であり、**確定した表記ルールではない**。

#### 表示情報（確定）

| 項目 | 内容 | 出典 |
|---|---|---|
| 拠点リスト | 拠点画像・拠点名・お気に入りアイコン | 【ワイヤ 1】 |
| 初期表示 | **ログインユーザーのお気に入り拠点と紐づくコート**を表示 | 【要求「予約検索・フィルター機能」】 |
| 初期表示（お気に入り無し） | **拠点の登録順に左から表示** | 【要求 同上】 |
| 時間軸 | **10:00 〜 22:00 / 30分刻み** | 【要求 概要】【ワイヤ 1】 |
| コート行 | コートごとに1レーン | 【要求 概要】【ワイヤ 1】 |
| 予約ブロック | 開始時間 / 終了時間 / タイトル / 定員 | 【ワイヤ 1】 |
| 日付 | 日付ピッカーで指定した日の予約状況 | 【要求「日付を指定すると対象の拠点/コートを表示」】 |
| 必要データ | 拠点一覧、コート一覧、当日の予約一覧、ユーザーのお気に入りフラグ | 【ワイヤ 1】 |

#### 操作（確定）

| 操作 | 挙動 | 出典 |
|---|---|---|
| 拠点を選択 | その拠点でフィルターをかける | 【要求「メイン画面で拠点を選択することでフィルターをかける」】 |
| 日付を選択 | 対象日の拠点/コートを表示 | 【要求】 |
| お気に入りアイコンを押す | 拠点名に対する **ON/OFF フラグ**を切り替える | 【要求「お気に入りアイコンを設定し、ON/OFFフラグで管理する」】 |
| フィルター条件を保存 | 選択した拠点のフィルター条件を保存する | 【要求「各拠点を選択し、フィルター条件を保存する」】（保存単位・保存先UIは ※未確定） |
| 予約ブロックをクリック | **予約詳細モーダル（SCR-R03）を表示** | 【ワイヤ 1】 |
| 時間ズームを切替 | 30分 / 1時間 | 【ワイヤ 1】※記述矛盾（下記） |

#### ※記述矛盾：お気に入り上限

- 【要求「メンバー」】：「メイン画面から拠点のお気に入りを行う（**上限10件**）」
- 【要求「予約検索・フィルター機能」】：「お気に入り**上限は設けない**」

同一ドキュメント内で矛盾している。本書では確定させず、残タスク（U-11）に送る。UI側は「上限到達時の表示」の有無がこれに依存する。

#### ※記述矛盾：ズーム単位

- 【要求 概要】：「30分刻みのスイムレーンが表示される」
- 【ワイヤ 1】：「時間ズーム（30分/1時間）」

30分固定か可変かが未確定。残タスク（U-08）。

#### ロール差分（確定分のみ）

| 要素 | メンバー | チームリーダー | 拠点スタッフ | システム管理者 |

| お気に入り登録 | ○ | ○ | ※未確定 | ※未確定 |

### 4.4 SCR-R03 予約詳細モーダル

#### 目的

予約の内容を確認し、参加登録／取消、および権限があれば編集・削除を行う。

#### ワイヤー

```
┌────────────────────────────────────────────┐
│  予約タイトル                        [×]   │
├────────────────────────────────────────────┤
│  拠点 / コート名                           │
│  10:00 - 12:00  |  定員 6/9名              │
│                                            │
│  参加者リスト                              │
│   ・ユーザーA  ・ユーザーB  ・ユーザーC    │
│                                            │
│  キャンセルポリシー                        │
│   （予約者が記載した内容）                 │
│                                            │
│  参加者通知履歴（簡易）                    │
│                                            │
│  [ 参加する ] [ 参加を取り消す ]           │
│  [ 編集 ]（権限がある場合） [ 削除 ]       │
└────────────────────────────────────────────┘
```

#### 表示情報（確定）【ワイヤ 3】

予約タイトル / 拠点・コート名 / 時間 / 定員 / 参加者リスト / キャンセルポリシー / 参加者通知履歴（簡易）

#### 操作（確定）

| 操作 | 条件 | 出典 |
|---|---|---|
| 参加 / 参加取り消し | フリーで募集されている予約に参加登録できる | 【ワイヤ 3】【要求「メンバー」】 |

| 削除 | 同上。削除時は**参加登録者全員に通知**される | 【要求「予約」】 |
| チーム枠への参加申請 | チームリーダーが「他のチームが予約した空チーム欄」に申請 | 【要求「チームリーダー」】 |

#### 確定している業務ルール（UI に影響）

- **定員となった場合は予約不可**【要求「予約」】 → 満席時に参加ボタンを操作不能にする必要がある（表現は ※未確定）
- 予約情報が編集された場合、参加登録している全利用者にメールおよび**アプリ上で通知**【要求「キャンセルポリシー管理・通知機能」】

| チーム | 所属チーム / 承認待ちチーム。**所属チーム申請は1つのみ**、**リーグ戦所属チーム申請も1つのみ** |

| 履歴 | 過去の予約履歴（自分が参加した予約） |

### 4.8 SCR-V01 拠点管理（拠点スタッフ用）

#### 目的

自拠点の営業日時・コート・設備を管理し、イベント予約および利用不可設定を行う。

#### 表示情報・操作（確定）【ワイヤ 6】【要求「拠点」「コート」「拠点スタッフ」】

| ブロック | 確定内容 |
|---|---|
| 営業日・営業時間設定 | **カレンダー表示**を行い、**月／週／曜日を一括で営業・休業設定**できる。営業日内で営業時間を設定する |

| コート管理 | 追加 / 編集 / 削除、コート名の編集 |

| 利用不可設定 | 拠点スタッフが**予約を行うことで**コートを利用不可状態にする |

- 拠点スタッフは**自拠点のみ**管理・閲覧可能【要求「拠点スタッフ」】 → 拠点セレクタは自拠点に固定される（※補完：UI表現は未確定）
- 拠点スタッフの操作は全てログに記録される【要求】
