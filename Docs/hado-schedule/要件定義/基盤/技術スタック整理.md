# 技術スタック整理

最終更新：2026-07-26（ORM を Prisma に確定）

## 目的
Windows 上でローカル開発を行うための、Next.js と PostgreSQL を中心とした開発環境の技術スタックを整理します。

本番構成および技術選定の決定事項は `技術スタック提案.md` を参照してください。本ドキュメントはローカル開発環境の構築手順に限定します。

## 1. 基本構成

- サーバー OS: Windows
- フレームワーク: Next.js
- データベース: PostgreSQL
- パッケージマネージャ: npm
- リポジトリ管理: Git（推奨）

## 2. 開発環境構築手順

1. Node.js のインストール
   - Node.js 公式サイトから LTS 版をダウンロードしてインストール
   - `node -v` / `npm -v` で確認
2. PostgreSQL のインストール
   - PostgreSQL 公式サイトから Windows インストーラをダウンロードしてインストール
   - postgres ユーザーのパスワードを設定
   - ポート 5432 を利用
3. Git のインストール（推奨）
   - Git 公式サイトからインストール
4. Next.js プロジェクトの作成
   - `npx create-next-app@latest hado-schedules`
   - TypeScript、ESLint、Tailwind CSS などを必要に応じて選択
5. 必要なパッケージのインストール
   - `npm install`
   - `npm install @prisma/client`
   - `npm install -D prisma`
   - ※ `pg` は Prisma 導入により不要（Prisma が接続を担う）。既存の依存から外してよい
6. 環境変数設定
   - プロジェクトルートに `.env.local` を作成
   - 例: `DATABASE_URL=postgresql://postgres:パスワード@localhost:5432/hado_schedules_dev`
7. データベース作成
   - `createdb -U postgres hado_schedules_dev`
   - テスト用に `hado_schedules_test` も作成する
8. 開発サーバ起動
   - `package.json` があるディレクトリで `npm run dev`

## 3. Prisma（ORM / マイグレーション管理・採用確定）

- 初期化: `npx prisma init`
- クライアント生成: `npx prisma generate`
- マイグレーション作成: `npx prisma migrate dev --create-only` → 生成されたSQLに手書き分を追記 → `npx prisma migrate dev`

### 運用ルール（重要）

- **`npx prisma db push` は使用しない。** 予約の時間帯重複を防ぐ排他制約（`EXCLUDE USING gist`）と部分一意インデックスはマイグレーションSQLに手書きするため、`db push` はこれを失う
- **`npx prisma migrate reset` は開発・テストDBに対してのみ実行する**（DB全消去のため）
- 日時カラムは `@db.Timestamptz` を明示する
- 詳細は `技術スタック提案.md` の「Prisma 運用ルール」を参照
