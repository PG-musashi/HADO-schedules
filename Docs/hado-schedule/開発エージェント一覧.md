# 開発エージェント一覧

HADO コート予約システムの開発に使う Claude Code サブエージェントの索引です。
Web アプリケーション開発に必要な知見領域ごとに、**開発有識者**と**レビュー担当**を1名ずつ用意しています。

**定義の実体は `.claude/agents/` にあります**（Claude Code がそこから直接読み込むため、コピーは不要）。
このファイルは Obsidian から一覧を辿るための索引です。

## 前提としている技術構成（確定事項）

全エージェントがこの前提で動きます。変更したときは `.claude/agents/` 側の記述も更新してください。

| 項目 | 内容 |
|---|---|
| フレームワーク | Next.js 16.2.6（App Router）/ React 19 / TypeScript |
| スタイル | Tailwind CSS v4 |
| DB | PostgreSQL |
| ORM | **Prisma** |
| 本番環境 | **Windows Server**（オンプレ・セルフホスト） |
| CI/CD | GitHub Actions |
| 監視 | Zabbix |

未決事項: 認証方式（NextAuth 採用可否）、ログ集約先、Redis 要否、冗長化構成、RTO/RPO。

## 設計方針

- **開発有識者**は書き込み可能（全ツール）。設計・実装・ドキュメント作成を担当する。
- **レビュー担当**は原則 `Read` / `Grep` / `Glob` のみ（コード系レビュアーは検証コマンド実行のため `Bash` を追加）。**ファイルを書き換えない**。指摘までが仕事で、修正は開発有識者かユーザーが行う。
- 全レビュアーに「問題がなければ問題なしと言う」「憶測で断定しない」を明記し、指摘件数稼ぎを抑制している。
- 各エージェントは [アプリケーション要求機能.md](01_要件定義/アプリケーション要求機能.md) を一次情報として参照する。
- **実装しない機能**（チェックイン / 決済 / レビュー / レポート / 利用分析 / キャンセル待ち / 記載のない通知）は全エージェントで提案禁止。
- Next.js 16 / Tailwind v4 は学習データと差異があるため、実装系エージェントには `node_modules/next/dist/docs/` を読んでから書くよう指示している。
- Prisma で表現できない制約（`EXCLUDE USING gist` による予約時間帯の重複防止、部分一意インデックス）は**マイグレーションSQLへの手書きが必要**な旨を、DB・API・テストの各エージェントに明記している。

## 使い方

セッション中に名前を指定して呼び出します。

```
frontend-developer で予約作成フォームを実装して
backend-api-reviewer で今回の変更をレビューして
```

### 推奨フロー

1. `requirements-analyst` で仕様を固める → `spec-reviewer` でレビュー
2. `ui-ux-designer` / `database-architect` で設計 → 各レビュアーでチェック
3. `frontend-developer` / `backend-api-developer` / `auth-security-engineer` で実装
4. 対応するレビュアー + `security-reviewer` でレビュー
5. `qa-test-engineer` でテスト → `test-quality-reviewer` でレビュー
6. `devops-infra-engineer` でCI/CD・運用整備 → `infra-reviewer` でレビュー

## 定義を編集するとき

`.claude/agents/<エージェント名>.md` を直接編集してください。
編集後は Claude Code のセッションを再起動すると反映されます。
